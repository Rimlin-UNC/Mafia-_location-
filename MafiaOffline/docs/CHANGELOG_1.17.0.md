# 1.17.0 — безопасность команд и восстановление связи

## Реализовано
- Сервер принимает команды только от сокета, которому принадлежит playerId. Знание ID другого игрока больше не позволяет голосовать, подтверждать роль или выходить от его имени.
- Возврат через register и resync требует сохранённого случайного deviceId; офлайн-слот больше не захватывается по одному имени. Код партии проверяется при регистрации. Старые слоты без deviceId не восстанавливаются автоматически по имени.
- Каждая ночь, голосование/переголосование и последнее слово получают сохраняемую actionEpoch. Команда из старой эпохи не применяется: клиент получает персональный sync. Современные клиенты отправляют эпоху обязательно; старые клиенты без неё получают предложение обновиться.
- Нативный клиент и браузер удерживают один неподтверждённый ход в памяти и повторяют его. После обрыва повтор начинается только после актуального sync. Смена эпохи отменяет старую команду; повтор принятой команды лишь подтверждается, а не выполняется второй раз.
- ACK содержит эпоху. Старое подтверждение не удаляет новый ход.
- Нативный WebSocket использует протокольный heartbeat и один цикл восстановления вместо конкурирующих переподключений. Браузер не добавляет данные в переполненный исходящий буфер.
- Sync восстанавливает последние 40 публичных событий, не пересылая приватные проверки ведущего.
- Снимки сессии записываются последовательно; более ранняя запись не затирает более новую, а очистка завершает очередь.
- Проверяется Origin браузерного WebSocket; ограничены количество соединений (64), сообщения (16К символов), существующий лимит частоты теперь закрывает нарушителя. WebSocket-сжатие отключено для коротких секретных сообщений.
- HTTP: Vary для gzip, отдельные ETag сжатого/обычного представления, HEAD без тела, запрет лишних методов, ограниченная очередь статики. Заголовки nosniff/no-referrer/DENY.
- Статика получает версию в URL: обычный HTTP-кеш работает и на LAN без Service Worker. Неверсионированные адреса требуют проверки свежести. Одновременные чтения одного ресурса объединяются; повторные gzip-вычисления и двойной учёт памяти устранены.

## Границы гарантий
Это не обещание «пакеты никогда не теряются». Повтор защищает ход, пока процесс клиента жив и тур ещё актуален. После закрытия процесса его pending-команда не сохраняется на диск. ACK означает принятие в память ведущего, а не fsync: аварийное отключение телефона может потерять последнее состояние. События/звук не имеют долговечного журнала доставки; sync восстанавливает состояние и ограниченную публичную историю.

HTTP/WS в локальной сети остаются незашифрованными. deviceId здесь — случайное доказательство владения, не защита от перехвата активным нарушителем сети. Используйте доверенную WPA2/WPA3-сеть; для защиты от владельца точки доступа нужен отдельный проект HTTPS/WSS с доверенными сертификатами/сопряжением устройств.

P2P-ретрансляция НЕ включена: роли, ходы и состояние ведущего не раздаются другим телефонам. Анализ готовых технологий, причины и безопасный план публичного asset-relay: `NETWORK_RELIABILITY.md`.
