# Ошибка «Unsupported class file major version 69»

## Что произошло

```
BUG! exception in phase 'semantic analysis' in source unit '_BuildScript_'
Unsupported class file major version 69
```

**Version 69 — это Java 25.** У вас на компьютере установлена Java 25, и Flutter
запускает Gradle именно на ней. А Gradle 8.x на Java 25 работать не умеет —
он её просто не понимает.

Проблема **не в коде проекта**. Тот же самый код собирается без ошибок, если
запустить сборку на подходящей версии Java.

---

## Таблица совместимости

Официальная таблица Gradle (docs.gradle.org/current/userguide/compatibility.html):

| Java | Минимальная Gradle |
|---|---|
| 17 | 7.3 |
| 20 | 8.3 |
| 21 | 8.5 |
| 22 | 8.8 |
| 24 | 8.14 |
| **25** | **9.1** ← у вас эта Java |

Проект использует Gradle 8.9 и AGP (Android Gradle Plugin) 8.1. Поднимать Gradle
до 9.1 нельзя: между 8.x и 9.x ломающие изменения, за ней придётся тянуть новый
AGP, новый Kotlin и все плагины — это долгая и рискованная переделка.

**Правильное решение — собирать на Java 17.** Это штатная версия для AGP 8.x,
на ней проект и собирался.

---

## Решение: указать Flutter, какую Java использовать

### Шаг 1. Найдите Java 17

Скорее всего она уже есть — Android Studio ставит свою JDK. Проверьте эти пути:

```
C:\Program Files\Android\Android Studio\jbr
C:\Program Files\Android\Android Studio\jre
```

Проверить версию:

```powershell
& "C:\Program Files\Android\Android Studio\jbr\bin\java.exe" -version
```

Если увидите `17.x` или `21.x` — подойдёт. Если Java 25 или её нет, скачайте
**Eclipse Temurin JDK 17** (msi-установщик, бесплатно):
https://adoptium.net/temurin/releases/?version=17

### Шаг 2. Скажите Flutter использовать эту Java

Одна команда, запомнится навсегда:

```powershell
flutter config --jdk-dir "C:\Program Files\Android\Android Studio\jbr"
```

Или, если ставили Temurin отдельно:

```powershell
flutter config --jdk-dir "C:\Program Files\Eclipse Adoptium\jdk-17.0.13.11-hotspot"
```

Путь укажите свой — тот, где лежит папка `bin` с `java.exe`.

### Шаг 3. Проверьте

```powershell
flutter doctor --verbose
```

В выводе найдите строку `Java version` — должна быть 17 или 21, не 25.

### Шаг 4. Соберите

```powershell
flutter clean
flutter pub get
flutter build apk --release
```

Готовый файл: `build\app\outputs\flutter-apk\app-release.apk`

---

## Если Java 17 ставить не хочется

Разовый вариант — задать переменную только для текущего окна PowerShell:

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
flutter build apk --release
```

После закрытия окна настройка сбросится. Для постоянной работы лучше
`flutter config --jdk-dir`.

---

## Сборка из Android Studio

Если собираете кнопкой в самой Studio, а не из консоли:

**File → Settings → Build, Execution, Deployment → Build Tools → Gradle**
→ поле **Gradle JDK** → выберите версию 17 (обычно в списке есть
`jbr-17` или `Embedded JDK`).

## Что я изменил в проекте

В `android/gradle/wrapper/gradle-wrapper.properties` добавил комментарий
с описанием этой ошибки и способом лечения — чтобы в следующий раз не искать
причину заново.

Пробовал поднять Gradle до 8.9 (она поддерживает Java до 22), проверил —
проект с ней собирается без единой ошибки компиляции. Но откатил обратно
на 8.3 по одной причине: 8.9 заметно прожорливее по памяти, а моё окружение
сборки ограничено 2 ГБ ОЗУ. На вашем компьютере такого ограничения нет.

**Если у вас есть Java 21 или 22 и не хочется ставить 17** — просто замените
в этом файле `gradle-8.3-all.zip` на `gradle-8.9-all.zip`. Wrapper скачает
новую версию сам при первой сборке.

## Почему не обновить всё до Java 25

Разумный вопрос. Цепочка обновлений выглядит так:

```
Java 25 → Gradle 9.1+ → AGP 8.7+ → новый Kotlin → обновление всех плагинов
```

На каждом шаге ломаются вещи. В прошлых версиях я уже сталкивался с тем, что
`mobile_scanner` требует одну версию CameraX, AGP — другую, а
`flutter_foreground_task` — третью. Именно несоответствие версий CameraX роняло
приложение при открытии сканера в версии 1.0.2.

Java 17 — это LTS-релиз, официально поддерживаемый Android-инструментами.
Собирать на нём надёжнее, а на итоговый APK версия сборочной Java никак не влияет.
