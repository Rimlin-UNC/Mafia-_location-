# Версия 1.4.0 — единый код: сеть и игра в одном QR

> Раньше ведущий показывал два кода по очереди: сначала Wi-Fi, потом
> приглашение в игру. Теперь первым показывается **единый код** — в нём
> и сеть, и номер игры, и адрес ведущего.
>
> * **Игрок с приложением «Мафия»** сканирует его один раз: телефон
>   подключается к сети и входит в игру.
> * **Игрок без приложения (камера + браузер)** по-прежнему сканирует
>   два кода. Сделать для него один код нельзя — причина ниже, в §1.
>
> Совместимость: протокол игры не менялся, веб-клиент не менялся.
> Старый код-ссылка и ввод шести цифр работают как раньше.

**Что проверено, а что нет.** Формат кода и его разбор покрыты тестами;
в тестах повторены три алгоритма, которыми код сети читают Android и ZXing
(перенесены из исходников), — поле игры им не мешает. Нативная часть
собирается в CI в настоящий APK. **Ни на одном настоящем телефоне это
не запускалось**: устройств у меня нет. Не проверено главное — как единый
код читает камера iPhone и камеры производителей (Samsung, Xiaomi), и как
системное окно «Сохранить сеть?» ведёт себя на разных прошивках. Что именно
проверить — в §6.

---

## 1. Что возможно, а что нет

QR-код несёт одну строку, и камера телефона делает с ней одно действие:
либо подключает к сети (`WIFI:…`), либо открывает адрес (`http://…`).
Стандарта «подключи и открой» нет.

Адрес игры (`http://192.168.43.1:8088`) существует только внутри сети
ведущего. Пока телефон не в ней, ссылка никуда не ведёт. Поэтому основой
единого кода может быть только код сети — а камера, подключив сеть,
больше ничего не сделает.

Обойти это для браузера нечем:

| Идея | Почему не работает |
|---|---|
| Ссылка в QR вместо сети | До подключения к сети страница не откроется |
| Страница сама открывается после подключения (как в отелях) | Нужно управлять DNS и портом 80 точки доступа; без root на телефоне ведущего это недоступно |
| Адрес вида `mafia.local` | Сканировать всё равно нечего: адрес пришлось бы набирать руками |
| Два кода на одном экране | Отвергнуто ещё при появлении кода Wi-Fi: половина стола сканирует не тот |

Остаётся свой сканер: приложение читает из кода всё и само делает оба
действия. Отсюда и граница: **одно сканирование — только для игроков
с приложением**.

## 2. Формат (FR-10.1)

Обычный код сети с одним дополнительным полем `G:` в конце:

```
WIFI:T:WPA;S:Mafia-Host;P:game2024;G:482913@192.168.43.1;;
                                   └─ номер игры @ адрес ведущего
```

* Адрес попадает в код, только если это IPv4. Без него приложение найдёт
  игру поиском по сети (UDP, как при вводе цифр).
* Порт не пишется: он постоянный, 8088.
* Поле всегда **последнее**. ZXing ищет `S:`, `P:`, `T:` по первому
  вхождению во всей строке, а не по границам полей; чужое поле не должно
  оказаться раньше.
* В значении только цифры, точки и `@` — ни букв, ни двоеточий, чтобы
  ни один разборщик не принял его кусок за своё поле.

Как неизвестное поле читают телефоны — по исходникам:

| Разборщик | Что делает с `G:` |
|---|---|
| Android 14+, `WifiUriParser.parseZxingUri` | Явно пропускает (`UnsupportedUriPrefix Found`) |
| Android 10–13, `WifiQrCode.parseZxingWifiQrCode` | Делит по `;`, берёт только `T:` `S:` `P:` `H:` |
| ZXing, `WifiResultParser` | Ищет только свои префиксы |
| iPhone, камеры Samsung / Xiaomi, Google Lens | **Неизвестно** — исходников нет, проверять на телефоне |

На случай, если чья-то камера такой код не примет, в «Wi-Fi для игроков»
есть выключатель **«Единый код»** (FR-10.4). Выключен — первый код снова
обычный код сети, всё как в 1.3.0.

## 3. Что видит ведущий (FR-10.3)

В лобби две вкладки:

1. **«Один код»** — единый код, имя сети и пароль под ним, кнопка
   «Показать крупно». Открыта сразу.
2. **«Для браузера»** — прежняя ссылка на игру и шесть цифр.

Если за столом у всех приложение, вторая вкладка не нужна. Если есть
игроки с браузером — порядок прежний: они наводят камеру на первый код
(подключается Wi-Fi), ведущий переключает вкладку, они сканируют второй.

Wi-Fi не настроен или его код выключен — вкладок нет, показывается
ссылка на игру, как раньше.

## 4. Что происходит у игрока с приложением (FR-10.2)

«Я игрок» → «Сканировать QR» → единый код. Дальше само:

1. **Проверка.** Если ведущий уже отвечает (телефон в нужной сети),
   ничего не спрашиваем.
2. **Сеть.** Иначе открывается системное окно Android «Сохранить сеть?».
   Игрок нажимает «Сохранить» — система сохраняет сеть и подключается
   к ней. Это то же, что делает камера, прочитав код Wi-Fi.
3. **Ожидание.** Приложение раз в секунду спрашивает ведущего (`/ping`).
   Как только он ответил — вход в игру. Если имя было введено до
   сканирования, вход происходит без нажатий.
4. **Если само не подключилось** (через 12 секунд, либо сразу — когда
   окно закрыли или телефон так не умеет): на экране имя сети, пароль,
   кнопки «Открыть Wi-Fi» и «Пароль» (копирует). Опрос продолжается ещё
   три минуты: игрок выбрал сеть руками — вход продолжится сам.

Когда автоматического подключения нет:

| Случай | Что будет |
|---|---|
| Android 10 и старше | Окна сохранения сети в системе нет — ручное подключение с подсказкой |
| iPhone с приложением | Нативной части нет — ручное подключение с подсказкой |
| Сеть с WEP | Система через это окно WEP не принимает — вручную |
| В пароле есть нелатинские символы | Система такой пароль через это окно не принимает — вручную |
| Сеть уже сохранена в телефоне | Окно не показывается; телефон подключится сам, если не занят другой сетью, иначе — выбрать сеть в списке (пароль не нужен) |
| Только WPA3, без режима совместимости с WPA2 | Сеть сохраняется как WPA2 и, скорее всего, не подключится — вручную (не проверено) |

Новых разрешений приложение не просит: сеть добавляет система, а не оно.

| Сообщение «это код сети, игры в нём нет» | `lib/ui/player/qr_scan_screen.dart` |

**Исправление по пути (FR-10.5).** Сканер приложения искал в любой строке
шесть цифр подряд. Наведённый на код сети с паролем вроде `key 482913`,
он принял бы пароль за номер игры. Теперь код сети разбирается отдельно.

**Тесты.** `test/join_code_test.dart` — 56 тестов: сборка кода, три
алгоритма чтения кода телефонами на восьми сетях (в том числе с `;`, `:`,
`\`, кавычками и кириллицей в имени и пароле), размер QR, разбор, сканер,
обмен с системой, настройка. `test/host_alive_test.dart` — 3 теста
проверки `/ping` на настоящем локальном сервере.

Чего в тестах нет: экраны (лобби, вход) не запускаются; ход
`_ensureNetwork` (порядок шагов, таймеры 12 с и 3 мин) не покрыт;
Kotlin-код проверен только сборкой APK.

## 6. Что проверить на телефонах

1. **Камера iPhone и единый код:** предлагает ли подключиться к сети.
   То же — штатные камеры Samsung и Xiaomi, Google Lens. Если какая-то
   не читает — выключить «Единый код» и сообщить, какая.
2. **Приложение, Android 11+:** сканирование → окно «Сохранить сеть?» →
   вход в игру. Сколько секунд проходит до входа.
3. **Телефон уже в другой сети Wi-Fi** (домашний роутер): переключается
   ли сам после «Сохранить».
4. **Включён мобильный интернет:** у сети ведущего интернета нет, и часть
   телефонов продолжает слать запросы через сотовую связь. Тогда Wi-Fi
   подключён, а игра не находится — подсказка на экране советует выключить
   мобильный интернет. Проблема та же, что и у браузера (описана
   в `ПОЛНОЕ_ОПИСАНИЕ_ПРОЕКТА.md`, §14.1).
5. **Android 10 и старше, iPhone с приложением:** появляется ли карточка
   ручного подключения, работает ли «Открыть Wi-Fi».
6. **Читаемость:** единый код плотнее прежнего (при обычных имени
   и пароле — версия QR 4–5 вместо 3).
   Проверить с метра-двух, обычным и крупным.
