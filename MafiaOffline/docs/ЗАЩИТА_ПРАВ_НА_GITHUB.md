# Защита прав на GitHub: закрыть доступ и не потерять работу

Практическое руководство для ООО «Ямастер» по репозиторию
`Rimlin-UNC/Mafia-_location-`.

Дата: 12 ноября 2026. Состояние на момент написания: **публичный**, лицензия
в `LICENSE` — проприетарная, GitHub определяет её как `NOASSERTION` — это
**нормально**, см. §5.

---

## 0. Главное в трёх строках

1. **Закрывать нужно, но одна кнопка ломает две вещи:** защиту ветки и мой доступ
   к правкам. Обе чинятся, и обе — до или сразу после закрытия.
2. **Перенос в организацию ООО «Ямастер»** — не формальность: репозиторий на
   личной учётке `Rimlin-UNC` юридически не принадлежит компании. Это главная
   дыра в защите прав, важнее видимости.
3. **До закрытия сохраните копию.** После переключения в приват часть вещей
   может стать недоступной, а откатить видимость назад без последствий нельзя.

## 1. Что именно вы теряете, а что нет

### Не потеряете

| Что | Почему остаётся |
|---|---|
| Исходный код и история | Приватность — это доступ, а не потеря данных |
| Все ветки, теги, релизы | Остаются, меняется только круг тех, кто их видит |
| GitHub Actions | Работает, но **минуты становятся платными** — см. §6 |
| Правки через коннектор Arena | **Если** переподключить GitHub после смены видимости — §4 |
| Возможность вернуть публичность | Settings → Danger Zone, но см. предупреждение ниже |

### Потеряете, если не подготовиться

| Что | Когда | Чем чинится |
|---|---|---|
| **Защита `main`** (обязательные проверки CI перед слиянием) | Сразу при закрытии | GitHub Pro — §3 |
| **Мой доступ к правкам** | Сразу при закрытии, если коннектор не видит приватные репозитории | Переподключение — §4 |
| **Скачивание APK** из CI без входа в GitHub | Сразу | Только для авторизованных — §7 |
| **Бесплатные минуты CI** (сейчас безлимит) | Сразу | 2000 мин/мес на Free — §6 |

> ⚠️ **Про возврат в публичное состояние.** Технически кнопка есть. Но если
> репозиторий хоть раз побыл публичным с приватными коммитами, считать
> «выложенное никогда не утекало» нельзя: форки, клоны и кэши поисковиков
> живут своей жизнью. Возврат видимости — не отмена утечки.

## 2. Порядок действий

### Шаг 0. Сделать резервную копию (5 минут, обязательно)

Это не про недоверие к GitHub, а про то, что закрытие меняет доступы, и если
что-то пойдёт не так, у вас под рукой будет полная копия.

```bash
# Полная копия со всей историей, ветками и тегами
git clone --mirror https://github.com/Rimlin-UNC/Mafia-_location-.git \
  mafia-offline-backup-$(date +%F).git

# Проверка, что копия целая
cd mafia-offline-backup-*.git && git log --oneline -1 && git tag | wc -l
```

Ожидаемый результат: `main` на коммите-мердже последнего PR, теги `v1.0.5`,
`v1.0.6`, `v1.4.0` — три штуки.

Отдельно **скачайте артефакты**, которые вам нужны как файлы, а не как код:
APK из релиза v1.4.0 (см. §7, пока репозиторий публичный это делается без
входа).

### Шаг 1. Проверить, видит ли коннектор приватные репозитории

**До** закрытия, не после.

В Arena откройте настройки подключённых приложений → GitHub. Посмотрите,
какие репозитории перечислены. Ключевой вопрос: есть ли там **приватные**
репозитории, к которым у вас есть доступ?

- **Да, приватные видны** → коннектор использует токен с доступом к ним или
  установленное GitHub App с доступом «All repositories». После закрытия
  репозиторий останется доступен.
- **Нет, только публичные** → коннектор видит мир глазами «публичного
  пользователя». После закрытия он ослепнет: я перестану видеть проект и
  вносить правки.

Признак, по которому это видно у вас сейчас: коннектор видит ровно 4
репозитория, и **все четыре публичные**. Это косвенный признак, что доступ
идёт по публичному признаку, а не по списку разрешённых репозиториев. Точный
ответ даст только экран настроек.

### Шаг 2. Выбрать сценарий

| Сценарий | Когда подходит | Плюсы | Минусы |
|---|---|---|---|
| **A. Закрыть как есть** (рекомендую начать с этого) | Нужно быстро убрать публичный доступ | Одна кнопка, всё остаётся на месте | Защита `main` отключится; минуты CI станут платными |
| **B. Перенести в организацию «Ямастер»** | Компания должна быть правообладателем юридически | Права у компании, а не у физлица; Team-план даёт защиту ветки | Нужна регистрация организации (бесплатно), перенос репозитория |
| **C. Оставить публичным, защищать иначе** | Цель — «чтобы не воровали», а не секретность | Бесплатная защита ветки, безлимитный CI | Код видят все; копию собрать может любой |

Я советую **A сейчас, B — когда дойдут руки**. Причина: пока репозиторий на
личной учётке, любая запись «© ООО «Ямастер»» в файлах — это утверждение,
которое компания не может подтвердить технически. Перенос меняет владельца
репозитория, а не только видимость.

### Шаг 3. Закрыть репозиторий

**Через веб-интерфейс** (я этого сделать не могу — см. §8):

1. Откройте `https://github.com/Rimlin-UNC/Mafia-_location-`
2. **Settings** (вкладка справа вверху)
3. Прокрутите до самого низа — **Danger Zone**
4. **Change repository visibility** → **Change to private**
5. GitHub попросит ввести имя репозитория для подтверждения:
   `Rimlin-UNC/Mafia-_location-`
6. Нажмите **I understand, change repository visibility**

Что произойдёт:
- анонимный доступ закроется сразу;
- GitHub Actions продолжит работать, но минуты станут считаться;
- **защита `main` и rulesets отключатся** — увидите предупреждение на странице
  настроек ветки.

### Шаг 4. Сразу после закрытия — вернуть себе доступ

Проверьте, что я снова вижу проект. Если нет — §4. **Не откладывайте:** пока
доступ не восстановлен, вы работаете вслепую.

## 3. Защита ветки: что было, что станет, чем заменить

### Как сейчас (публичный репозиторий, Free)

Защита `main` на публичном репозитории на Free **доступна бесплатно**. У вас
она настроена частично: в прошлых ходах вы ставили правило с тремя
обязательными проверками.

### Что станет после закрытия

На **приватном** репозитории защита ветки и rulesets на Free **не работают**.
Это ограничение тарифа, а не настройка, которую забыли включить. Попытка
включить через API вернёт:

```
403: Upgrade to GitHub Pro or make this repository public to enable this feature
```

(в приватном случае текст будет про GitHub Pro).

### Три варианта

**Вариант 1 — GitHub Pro, $4/мес.** Защита ветки и rulesets на приватных
репозиториях; 3000 минут CI вместо 2000. Для одного разработчика это самый
простой путь: то же поведение, что сейчас, ничего не переделывать.

> ⚠️ Про Pro есть противоречивые данные. Документация GitHub и часть
> обсуждений говорят, что Pro включает защиту ветки для приватных репозиториев
> личного аккаунта. Другая часть пользователей сообщает, что настройка остаётся
> неактивной и требует организации с планом Team. Судя по обсуждениям
> последних недель, у части аккаунтов это заработало после активации Pro, у
> части — нет. **Проверьте на своём аккаунте до оплаты:** включите Pro на
> месяц, откройте Settings → Branches и посмотрите, активно ли правило. Если
> написано «move to a Team organization» — Pro не поможет, нужен Team (см.
> вариант 2).

**Вариант 2 — организация на ООО «Ямастер» с планом Team, $4/пользователь.**
Защита ветки гарантированно работает; плюс решает главную проблему — репозиторий
принадлежит компании. Регистрация организации бесплатна, платить нужно только
за Team.

**Вариант 3 — остаться на Free и защищаться процессом.** Технически GitHub не
запретит слить красный PR. Компенсация:

- продолжать работать только через PR, как сейчас;
- в CI **уже есть** проверки — они выполнятся и покажут статус, просто не
  заблокируют слияние;
- добавить в `CODEOWNERS` себя — это не блокирует, но напоминает;
- проверять `gh pr checks N` перед `gh pr merge`.

Честно: это дисциплина, а не защита. Один усталый вечер — и в `main` уедет
красный код.

### Что я советую

**Free + закрытый репозиторий + процесс через PR** на первое время. Защита
ветки — вопрос удобства, а не прав. Затем — организация и Team, если правки
пойдут регулярно.

## 4. Как вернуть себе возможность править код через коннектор

Это самая частая точка, где люди теряют работоспособность после закрытия.

### Почему может сломаться

Коннектор GitHub в Arena работает от имени токена. Если токен — **fine-grained**
и выдан на конкретные репозитории, которые были публичными, после смены
видимости он может перестать их отдавать. Симптом: я пишу «нет доступа к
репозиторию» или вижу пустой список файлов.

### Как починить

**Способ 1. Переподключить GitHub в Arena (самый простой).**

1. В Arena откройте настройки подключённых приложений → GitHub.
2. Отключите подключение.
3. Подключите заново, **внимательно читая экран разрешений**.
4. На экране выбора репозиториев выберите:
   - либо **All repositories** — тогда приватные тоже видны;
   - либо **Only select repositories** и явно отметьте
     `Rimlin-UNC/Mafia-_location-`.
5. Сохраните. Проверьте, что репозиторий появился в списке.

**Способ 2. Личный токен (если коннектор не даёт выбрать приватные).**

1. GitHub → Settings (личный, не репозитория) → **Developer settings** →
   **Personal access tokens** → **Fine-grained tokens** → **Generate new token**.
2. **Repository access**: Only select repositories →
   `Rimlin-UNC/Mafia-_location-`.
3. **Permissions** — минимально необходимые:
   - `Contents: Read and write` — правки файлов;
   - `Pull requests: Read and write` — создание и слияние PR;
   - `Workflows: Read and write` — правки `.github/workflows/`;
   - `Actions: Read` — смотреть результаты CI;
   - `Metadata: Read` — обязательное, ставится само.
4. Срок действия — 90 дней (не «без срока»: украденный бессрочный токен
   работает вечно).
5. Скопируйте токен и передайте его в настройки коннектора.

**Способ 3. Локальная работа (всегда доступна).**

Если коннектор подведёт, код всё равно можно править: `git clone` приватного
репозитория по SSH или по токену, работать локально, пушить. Возможности
Arena — удобство, а не единственный путь.

### Что останется работать точно

- Чтение и правка файлов — после переподключения.
- PR, слияния, CI — после переподключения.
- **Публикация релизов** — работает, но учтите: `release.yml` создаёт релиз
  через `GITHUB_TOKEN` с `permissions: contents: write`, ему видимость
  безразлична.

## 5. Какую лицензию ставить на GitHub

### Что написано сейчас

В `LICENSE` — проприетарная лицензия ООО «Ямастер». GitHub показывает её как
**`NOASSERTION`** вместо `MIT` или `Apache-2.0`. **Это правильное поведение, а
не ошибка.**

Причина: GitHub распознаёт только ~20 стандартных лицензий с точным текстом.
Свой текст он не может классифицировать, поэтому честно пишет «другая».
Для проприетарной лицензии это единственный возможный вариант — и он лучше,
чем подделка под MIT.

### Что выбрать в выпадающем списке при создании файла

GitHub предлагает список шаблонов. **Не выбирайте ничего из него.**

Не берите:
- **MIT, Apache-2.0, BSD, GPL, AGPL, MPL, Unlicense** — все они разрешают то,
  что вы запрещаете. Особенно MIT и Apache: они прямо разрешают коммерческое
  использование и создание производных без вашего согласия.
- **«None»** в интерфейсе создания репозитория — означает «нет файла
  лицензии», а не «все права защищены». Разница юридическая: без файла сложнее
  показать, что вы обозначили условия.

Правильно: **оставить свой текст** в `LICENSE`, который уже лежит в
репозитории. Это нормальная практика — так делают многие коммерческие
продукты.

### Что ещё стоит добавить в репозиторий

| Файл | Зачем | Статус |
|---|---|---|
| `LICENSE` | Условия использования | ✅ есть |
| `docs/ОФЕРТА.md` | Публичная оферта для пользователей | ✅ есть |
| `COPYRIGHT` или шапка в каждом файле | Явная принадлежность | ⬜ можно добавить |
| `SECURITY.md` | Куда сообщать об уязвимостях | ⬜ стоит добавить |
| `CODEOWNERS` | Кто владелец кода | ⬜ полезно при работе в организации |

### Важное ограничение, которое нельзя обойти

**Лицензия не действует задним числом.** Кто получил код под MIT до замены —
сохранил права по MIT: копировать, менять, продавать. Ни смена лицензии, ни
закрытие репозитория это не отменяет.

Что реально можно сделать:
- всё, что выпущено после замены, — под проприетарной;
- **удалить старые релизы и теги**, если под ними был MIT-код: это не отзовёт
  уже скачанное, но уберёт источник;
- если MIT-копий было много и это критично — юридическая работа с
  распространителями, а не техническая.

## 6. GitHub Actions: что станет платным

### Сейчас

Публичный репозиторий → **безлимитные минуты** на стандартных раннерах.
Поэтому `flutter analyze`, сборка APK на каждый PR и релизы бесплатны.

### После закрытия

Приватный репозиторий на Free → **2000 минут в месяц**, дальше
$0.006/минуту (Linux). У вас же на каждый PR: анализ и тесты (~1 мин) +
сборка APK (~4–5 мин) + Python-стенды + веб-проверка ≈ **6–7 минут**.

| Режим работы | Минут в месяц | Хватает? |
|---|---|---|
| 20 PR в месяц | ~130 | ✅ с запасом |
| 100 PR в месяц | ~650 | ✅ |
| 250 PR в месяц | ~1650 | ⚠️ близко к лимиту |

Плюс **хранилище артефактов: 500 МБ**. Один APK — 34 МБ, держится 14 дней.
Параллельно лежит 2–6 сборок = 70–200 МБ. **Это узкое место, а не минуты.**

### Что сделать заранее

1. **Поставить лимит расходов**, чтобы не получить счёт:
   Settings (личный аккаунт) → **Billing and plans** → **Spending limits** →
   включить лимит `$0`.
2. **Сократить хранение артефактов** с 14 до 7 дней — экономия вдвое, вам
   хватит: сборка нужна для проверки и установки «до слияния».
3. **Добавить отмену устаревших прогонов**, чтобы не жечь минуты на PR,
   которые вы обновили:

```yaml
# в .github/workflows/ci.yml, сразу после блока permissions
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true
```

Я не вносил это в код: вы просили инструкцию, а не правки. Скажете — внесу
отдельным PR.

## 7. Релизы и APK после закрытия

**Релизы останутся**, но станут видны только тем, у кого есть доступ к
репозиторию. Ссылка `releases/latest` перестанет работать для посторонних.

Это важно, если APK вы даёте игрокам ссылкой. После закрытия вариантов два:

| Вариант | Как | Кому подходит |
|---|---|---|
| Раздавать файл напрямую | Скачать APK, отправить в мессенджере / на диск / по QR на файлообменник | Проще всего для 5–20 человек |
| Публичный репозиторий только для релизов | Отдельный публичный репозиторий с одним README и APK в релизах, исходников там нет | Если нужна постоянная ссылка |

Второй вариант интересен тем, что **не раскрывает код**: публичный репозиторий
может содержать только собранные APK. Но его придётся поддерживать отдельно.

> ⚠️ Скачивание артефактов CI (не релизов) требует входа в GitHub. Если APK
> вам нужен как файл — забирайте его из релиза, пока репозиторий ещё публичный,
> или после закрытия через веб-интерфейс под своей учётной записью.

## 8. Что я не смог сделать за вас и почему

Проверено фактически, не на словах:

| Действие | Результат | Причина |
|---|---|---|
| Сменить видимость через API | `403 Resource not accessible by integration` | Токен коннектора не имеет прав администрирования репозитория |
| Включить защиту ветки | `403` | То же + на приватном Free недоступно в принципе |
| Прочитать секреты Actions | `403` | Нет прав на secrets |
| Изменить настройки Actions | `403` | Нет прав |

При этом по правам пользователя вы **админ репозитория**
(`permissions.admin = true`), но сам токен выпущен с урезанным набором
разрешений: заголовок `x-oauth-scopes` приходит пустым, а
`x-accepted-github-permissions` указывает `allows_permissionless_access=true`.
Отсюда расхождение: учётная запись может всё, а конкретный токен — только
чтение и запись кода.

**Вывод:** смену видимости, защиту ветки и лимиты придётся сделать в
веб-интерфейсе. Это 5–7 минут работы, все шаги в §2 и §3.

## 10. Итог: что даст закрытие, а что нет

**Даст:**
- публичный доступ к исходникам закрыт;
- новые копии никто не соберёт без вашего ведома;
- релизы не видны посторонним.

**Не даст:**
- не отменит MIT у тех, кто получил код раньше;
- не докажет, что правообладатель — ООО «Ямастер», пока репозиторий на личной
  учётке;
- не помешает тому, у кого уже есть скачанная копия.

**Настоящая защита прав — это три вещи вместе:**
1. репозиторий принадлежит организации ООО «Ямастер»;
2. проприетарная лицензия и оферта (✅ уже сделано);
3. договоры с теми, кто получает доступ к коду.

Закрытие видимости — самое простое из трёх и самое переоценённое.
