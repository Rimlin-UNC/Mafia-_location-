# Версия 1.0.3 — исправление краха сканера QR

## Причина падения найдена

Крах вызывал **не сам сканер, а моя правка в прошлой сессии**.

Тогда сборка падала с ошибкой «CameraX 1.5.0 требует AGP 8.6, а у вас 8.1». Вместо того чтобы взять подходящую версию сканера, я принудительно понизил CameraX до 1.3.4:

```gradle
resolutionStrategy {
    force 'androidx.camera:camera-core:1.3.4'   // ← причина краха
    ...
}
```

Сборка прошла, но `mobile_scanner 6.0.11` **скомпилирован под CameraX 1.5**. Он вызывал методы, которых в 1.3.4 нет. Пока сканер не открывали, всё работало; при нажатии «Сканировать QR» подгружался класс камеры → `NoSuchMethodError` → мгновенное закрытие приложения без диалога об ошибке.

Классическая ошибка: я «починил» сборку ценой рантайма и не мог этого заметить, потому что телефона для проверки нет.

---

## Что исправлено

### 1. Правильная версия сканера вместо форса версий

`mobile_scanner` понижен с 6.0.11 до **5.2.3** — он собран под CameraX **1.3.3**, совместимую с нашим AGP 8.1 без ухищрений. Блок `resolutionStrategy` удалён полностью: несоответствия версий больше нет.

### 2. Разрешение камеры запрашивается явно

В 1.0.2 разрешения в манифесте были, но в рантайме их никто не спрашивал — на Android 6+ это обязательно. Добавлен `permission_handler`: разрешение запрашивается **до** создания контроллера камеры. При отказе показывается экран с кнопкой «Открыть настройки», а не пустота.

### 3. Контроллер камеры запускается корректно

Раньше контроллер создавался в поле класса и никогда не стартовал явно. Теперь по официальному паттерну пакета:

- создаётся только после выдачи разрешения;
- запускается через `await controller.start()` внутри `try/catch`;
- освобождается после `super.dispose()`, как требует документация.

### 4. Обработка жизненного цикла

Добавлен `WidgetsBindingObserver`: при сворачивании приложения камера останавливается, при возврате — запускается снова. Без этого камера оставалась занятой, и следующее открытие сканера падало.

### 5. Ни одного необработанного исключения

Весь путь обёрнут в `try/catch`. Любая проблема — нет камеры, занята другим приложением, отказ в разрешении — теперь приводит к понятному экрану с кнопкой «Ввести код вручную». Приложение не закроется ни при каком сценарии.

### 6. Парсер QR понимает оба формата

Веб-версия сменила формат кода, поэтому парсер читает и новый `http://IP:PORT/?g=482913`, и старый `mafia://IP:PORT/482913`, и просто шесть цифр. Проверено 11 тестами, включая чужие QR и мусорные строки — все отклоняются корректно.

Впредь: `1.0.4+4`, `1.0.5+5` — `versionCode` обязан расти, иначе Android откажется ставить обновление поверх установленного.

## Как собрать APK

Если в папке нет свежего `MafiaOffline-1.0.3-*.apk`, значит сборка в песочнице не уложилась в лимиты: окружению нужно около 3 ГБ ОЗУ, здесь доступно 1.2 ГБ, и Gradle убивает OOM killer. На обычном компьютере это 3–5 минут:

```bash
# (вы уже в папке MafiaOffline — корне проекта)
flutter pub get
flutter build apk --release
```

Готовый файл: `build/app/outputs/flutter-apk/app-release.apk`

На машине с 8+ ГБ ОЗУ стоит поднять лимиты в `android/gradle.properties` — сборка пойдёт заметно быстрее:

```properties
org.gradle.jvmargs=-Xmx3g -XX:MaxMetaspaceSize=1g
kotlin.compiler.execution.strategy=daemon
```

## Что проверить после установки

1. **Главное:** нажать «Сканировать QR» — приложение должно запросить камеру и открыть видоискатель, а не закрыться.
2. Отказать в разрешении — должен появиться экран с кнопкой «Открыть настройки».
3. Свернуть приложение на экране сканера и вернуться — камера должна ожить.
4. Отсканировать QR ведущего — код и адрес подставятся автоматически.
5. Навести на посторонний QR — сообщение «Это не код игры», без краха.
