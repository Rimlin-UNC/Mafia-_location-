## 1. Паспорт проекта и ключевая концепция

| Параметр | Значение |
|---|---|
| **Название приложения** | Мафия Offline (`mafia_offline`) |
| **Android `applicationId`** | `com.example.mafia_offline` |
| **Текущая версия** | `1.0.5+5` (`versionName = 1.0.5`, `versionCode = 5`) |
| **Технологический стек** | Flutter 3.24.x (Dart `>=3.0.0 <4.0.0`) + Vanilla JS/HTML/CSS (веб-клиент) |
| **Сетевой стек** | Чистый `dart:io` (`HttpServer` + `WebSocketTransformer` на `:8088`, `RawDatagramSocket` UDP на `:45455`) |
| **Требование к интернету** | **Не требуется (100% офлайн)**. Работает через точку доступа телефона ведущего или общий локальный Wi-Fi роутер |
| **Кто устанавливает APK** | **Только ведущий** (1 Android-смартфон) |
| **Как заходят игроки** | Сканируют камерой QR-код у ведущего и играют **в обычном мобильном браузере** (Android, iPhone, планшет, ноутбук) |
| **Подпись сборок 1.0.4 / 1.0.5** | SHA-256: `117b5d7eb24ec6e183bc62088fdc452db4b5cee4d8327ef7f7ffabae8c9b6dff` (файл `keystore/debug.keystore`) |

### Главная продуктовая идея (с версии 1.0.5)

Изначально APK предполагалось ставить всем участникам, но на живых играх это создаёт барьер (владельцы iPhone, запрет установки из неизвестных источников на Android, трата времени за столом). Поэтому принята архитектура **«Один APK-сервер + локальный веб-сайт для игроков»**:

1. Телефон ведущего поднимает внутри Flutter-приложения локальный HTTP и WebSocket сервер на порту `8088`.
2. В лобби ведущий поочерёдно показывает **два QR-кода**:
   - **Шаг 1 (при необходимости): QR подключения к Wi-Fi** стандарта `WIFI:T:WPA;S:...;P:...;;` — камеры iOS и Android подключаются к точке доступа без ручного ввода пароля.
   - **Шаг 2: QR входа в игру** `http://<IP_ВЕДУЩЕГО>:8088/?g=<6_ЗНАЧНЫЙ_КОД>` — открывает в браузере веб-клиент с уже подставленным кодом партии.
3. Браузерный игрок получает **100% функциональности нативного клиента**: иллюстрированную карту роли с переворотом и маскировкой, памятку по роли, ночные ходы, голосование, второй тур, лог зрителя, вибрацию, удержание экрана и синхронный со всеми телефонами звук.
4. **Нативный режим игрока внутри APK** не удалён, а **спрятан** как резервный вариант (включается через *Настройки звука → Дополнительно → «Режим игрока в приложении»*). Нативный и браузерный клиенты общаются с сервером по **одному и тому же протоколу** и могут участвовать в одной партии одновременно.

### Почему отвергнуты альтернативные транспорты

1. **Почему не Bluetooth / BLE:** в стеке Android жёстко зашит лимит `BTA_GATTC_CONN_MAX = 7` (на практике многие чипсеты стабильно держат лишь 4–6 одновременных GATT-соединений). Для стола на 6–20 игроков Bluetooth непригоден.
2. **Почему не Flask + ngrok:** Python/Flask невозможно прозрачно запустить внутри обычного Android APK без установки Termux и консольных команд, а ngrok требует выхода во внешний интернет (нарушает главное требование автономности). Встроенный `HttpServer` из стандартной библиотеки `dart:io` поднимается в том же процессе без единой внешней зависимости и выдерживает залповое подключение 20 игроков за ~1.2 секунды.

#### Ресурсы (`assets/`)
- `assets/web/` — полный одностраничный веб-клиент для браузерных игроков:
  - `index.html` — разметка всех экранов (вход, лобби, защитный экран роли, игровой стол, шторка роли, фатальные экраны, итог партии).
  - `style.css` — тёмная адаптивная вёрстка, включая компактный режим для малых экранов (`320×568`).
  - `app.js` — вся клиентская логика: WebSocket-клиент, экспоненциальный реконнект с джиттером, сторожевой таймер, расчёт времени по дедлайну, очередь неподтверждённого хода, NTP-синхронизация часов и Web Audio API.
  - `sw.js` — Service Worker для офлайн-кеширования статики и выживания при кратковременном обрыве Wi-Fi.
  - `manifest.webmanifest` — PWA-манифест для установки ярлыка на домашний экран без адресной строки.
- `assets/cards/` — полноразмерные иллюстрации карт (`700×1050`, для APK) и подкаталог `assets/cards/web/` (`560×840`, прогрессивный JPEG, вдвое легче — отдаются браузерам).

## 4. Модели данных и игровой движок (`GameEngine`)

Вся математика правил изолирована в `lib/core/game_engine.dart` и `lib/models/game_state.dart` — без привязки к Flutter UI и сокетам.

### 4.1. Роли и стороны (`lib/models/role.dart`)

| `RoleType` | Название | Сторона (`Side`) | Ходит ночью | Приоритет ночи (`nightOrder`) | Особенность |
|---|---|---|---|---|---|
| `prostitute` | Проститутка 💋 | `Side.civilians` | Да | **1** | Блокирует выбранного игрока (отменяет его ночной ход; себя выбирать нельзя) |
| `doctor` | Доктор 💉 | `Side.civilians` | Да | **2** | Спасает одну цель от убийства мафии и маньяка. Не может лечить одного и того же игрока две ночи подряд (`lastHealedId`), себя лечить может |
| `mafia` | Мафия 🔫 | `Side.mafia` | Да | **3** | Голосует за общую жертву команды мафии (своих выбирать нельзя) |
| `don` | Дон 🎩 | `Side.mafia` | Да | **3** | Глава мафии: если Дон сделал выбор, его голос **решающий** и перекрывает голоса рядовой мафии. Для Комиссара выглядит **мирным** |
| `maniac` | Маньяк 🔪 | `Side.solo` | Да | **4** | Независимо убивает ночью любого игрока. **Одиночка** (v1.1.0): побеждает, только оставшись единственным живым |
| `commissioner` | Комиссар 🔎 | `Side.civilians` | Да | **5** | Проверяет одного игрока (кроме себя). Возвращает `true` только на `RoleType.mafia` (`don` даёт `false`) |
| `civilian` | Мирный житель 👤 | `Side.civilians` | Нет | 99 | Ночью спит, днём обсуждает и голосует |

> **Примечание:** с v1.1.0 маньяк снова `Side.solo` (классика). В 1.0.4–1.0.6 он числился за городом — старые записи истории читаются по сохранённой в них роли. Условия победы: `WinnerSide.maniac` — когда маньяк остался один.

### 4.2. Алгоритм раздачи ролей (`GameEngine.assignRoles`)

Роли раздаются **строго в момент нажатия ведущим «Старт игры»**, по фактическому числу вошедших игроков:
1. Специальные роли собираются в пул в порядке убывания важности: `don → mafia → doctor → commissioner → prostitute → maniac`.
2. Если игроков пришло меньше, чем сумма заказанных спецролей, лишние роли срезаются с конца (первым отбрасывается `maniac`, затем `prostitute` и т.д.).
3. **Гарантия стартового баланса:** если `players.length - mafiaCount <= 1`, лишние мафиози автоматически разжалуются в `civilian` (сначала рядовая `mafia`, в последнюю очередь `don`), чтобы партия не завершалась мгновенной победой мафии на нулевой секунде.
4. Оставшиеся места заполняются `RoleType.civilian`.
5. Пул перемешивается криптостойким генератором `Random.secure()` по алгоритму Фишера — Йетса.

### 4.3. Алгоритм разрешения ночи (`GameEngine.resolveNight`)

Строгая последовательность шагов:
1. **Блокировка:** если жива Проститутка, фиксируется `blockedId = nightActions[prostitute.id]`.
2. **Лечение:** если жив Доктор и его `id != blockedId`, и выбранная цель `target != lastHealedId`, фиксируется `healedId = target`.
3. **Выстрел мафии:** выстрел мафии блокируется **только если вся живая команда мафии состоит из одного человека и именно он заблокирован** (`team.every((m) => m.id == blockedId)`). Иначе вызывается `resolveMafiaTarget`:
   - если жив Дон и он прислал непустую цель, берётся выбор Дона (даже если сам Дон был заблокирован при наличии живых сообщников — *учитывайте эту деталь, если захотите менять правило блокировки Дона*);
   - иначе считается большинство голосов членов мафии (при равенстве — случайный выбор среди лидеров).
4. **Выстрел маньяка:** если жив Маньяк и его `id != blockedId`, фиксируется `maniacTarget`.
5. **Проверка комиссара:** если жив Комиссар и его `id != blockedId`, вычисляется `checkIsMafia = (target.role.type == RoleType.mafia)`.
6. **Итоговые жертвы (`killedIds`):** в список добавляется `mafiaTarget` (если `!= healedId`) и `maniacTarget` (если `!= healedId` и ещё не в списке). Доктор одним лечением спасает цель сразу от обоих покушений.

Перед оглашением утра ведущий видит шторку `NightResultSheet` (`state.pendingNight`), где при необходимости может вручную скорректировать список жертв методом `editNightOutcome()`, после чего вызывает `announceNight()`.

### 4.4. Машина состояний фаз и голосование

```text
waiting (Лобби)
   │ startGame() → раздача ролей + startNight()
   ▼
night (Ночь N) ──[все сходили / таймер / кнопка ведущего]──▶ finishNight() (пауза, шторка сводки у ведущего)
   ▲                                                               │ announceNight()
   │                                                               ▼
   │                                                      _checkGameOver()? ──да──▶ ended
   │                                                               │ нет
   │                                                               ▼
   │                                                          day (День N)
   │                                                               │ [таймер / кнопка «К голосованию»]
   │                                                               ▼
   │                                                        voting (1-й тур)
   │                                                               │ closeVoting() (пауза, шторка у ведущего)
   │                                                  ┌────────────┼────────────┐
   │                             startRunoff(leaders) │            │            │ confirmElimination(id / null)
   │                                                  ▼            │            ▼
   │                                          voting (2-й тур) ────┘    _checkGameOver()? ──да──▶ ended
   │                                                                            │ нет
   └────────────────────────────────────────────────────────────────────────────┘
```

### 4.5. Условия победы (`GameState.checkWinner`) — классические (v1.1.0)

Порядок проверок важен: он решает, кому достанется победа в спорном раскладе.

- `alive.isEmpty` → `WinnerSide.nobody` (ничья — погибли все).
- Жив **только маньяк** (`maniac > 0, mafia == 0, civilians == 0`) → `WinnerSide.maniac`.
- Нет ни мафии, ни маньяка (`mafia == 0 && maniac == 0`) → `WinnerSide.civilians`.
- `mafia >= civilians` (город без учёта маньяка) → `WinnerSide.mafia`:
  при равенстве город уже не может выгнать мафию голосованием.
- Иначе `null` — партия продолжается.

Отличия от v1.0.4–1.0.6 («играем до последнего»):
- мафия побеждала только при `civilians + maniac <= 1`, то есть при равенстве игра шла дальше;
- маньяк числился за городом и делил с ним победу, отдельного `WinnerSide.maniac` не было.

### 4.6. Тайминги (`Rules`) и формула баланса

- **Ночь:** `20 + 10 × (число живых активных ночью ролей)` сек.
- **День:** `min(600, 45 × число живых)` сек.
- **Голосование (1-й тур):** `20 + 4 × число живых` сек.
- **Второй тур (`runoff`):** `15 + 3 × число живых` сек.
- **Индикатор баланса на экране создания игры (`SetupScreen`):** использует откалиброванный по симуляциям индекс `index = (mafiaCount / sqrt(totalPlayers)) * 2` с порогами `1.8` (перевес мафии), `1.15` (умеренный перевес / норма), `0.65` (перевес города), плюс жёсткое предупреждение, если `mafiaCount >= others - 1`.

## 5. Сетевой уровень и спецификация WebSocket-протокола

### 5.1. Конверт сообщения (`Envelope`, `lib/net/protocol.dart`)

Каждое сообщение по WebSocket (в обе стороны) представляет собой плоский JSON-объект UTF-8 со служебными полями `v`, `ts`, `type` и данными верхнего уровня:

```json
{
  "v": 1,
  "ts": 1753542000123,
  "type": "night_action",
  "playerId": "p1753541990001234",
  "targetId": "p1753541990005678"
}
```

Если поле `v` не равно `Net.protocolVersion` (`1`) или пакет не парсится, он молча отбрасывается.

### 5.2. Сообщения Игрок → Ведущий

| `type` | Поля полезной нагрузки | Описание и реакция сервера |
|---|---|---|
| `register` | `name: String`, `code?: String` | Первичный вход или возврат по имени. Сервер **сначала** ищет игрока с таким именем без учёта регистра: если он есть и **офлайн** — возвращает в тот же слот (`reclaimed` + `sync`) даже посреди идущей игры; если онлайн — шлёт `register_denied (name_taken)`. Если имя новое — пускает только в фазе `waiting` при числе игроков `< 20`, иначе отказывает (`game_started` / `game_full`) |
| `resync_request` | `playerId?: String`, `name?: String` | Запрос актуального состояния после обрыва связи или выхода из фона. Ищет игрока по `playerId`, а если не найден (очищен `localStorage`) — по `name`. Отвечает парой `reclaimed` + `sync` и отрубает старые дубли вкладок |
| `role_ack` | `playerId: String` | Игрок открыл и подтвердил ознакомление со своей ролью (`roleAcknowledged = true`) |
| `night_action` | `playerId: String`, `targetId: String \| null` | Ночной ход (`null` — пропуск хода). Принимается только в фазе `night` от живой активной роли, один раз за ночь. Отвечает `ack`. Если все сходили — вызывает `finishNight()` |
| `vote` | `playerId: String`, `targetId: String \| null` | Голос на дневном голосовании (`null` — воздержался). Во втором туре голоса не из `runoffCandidates` превращаются в `null`. Отвечает `ack`. Если проголосовали все живые — вызывает `closeVoting()` |
| `ping` | `t: int` (локальный `DateTime.now()` клиента), `rtt?: int` | Обрабатывается прямо в `HostServer` без захода в `HostController`: обновляет `lastSeen`, сохраняет лучший `rtt`, мгновенно отвечает `pong` |

## 6. Раздача веб-клиента и оптимизация трафика (`HostServer` + `WebAssets`)

Телефон ведущего одновременно раздаёт Wi-Fi и держит до 20 соединений. Чтобы он не захлебнулся и не упал по OutOfMemory при одновременном сканировании QR двадцатью игроками, реализованы 6 механизмов:

1. **Семафор отдачи статики (`_maxParallelStatic = 4` в `HostServer`):** одновременно читаются и отправляются не более 4 HTTP-ответов, остальные запросы ждут своей очереди миллисекунды в `_staticQueue`. Пиковое потребление памяти под буферы ограничено.
2. **LRU-кеш ассетов с потолком 6 МБ (`WebAssets._maxCacheBytes`):** в памяти держатся карты и короткие звуки; файлы крупнее половины потолка (3 МБ) не вытесняют весь кеш.
3. **Gzip-сжатие текстовых файлов:** `index.html`, `style.css`, `app.js`, `manifest.webmanifest` сжимаются один раз (экономия ~66–68%: `app.js` сжимается с 42 КБ до 13.5 КБ) и отдаются с `Content-Encoding: gzip`.
4. **Инъекция кода партии в HTML:** `index.html` отдаётся с `Cache-Control: no-store`, а строка `<script src="/app.js"></script>` на лету заменяется на:
   ```html
   <script>window.__MAFIA__={"code":"482913","v":"v5"};</script>
   <script src="/app.js?v5"></script>
   ```
   При смене партии вызывается `WebAssets.invalidateHtml()`.
5. **Облегчённые ассеты специально для браузеров (`WebAssets.resolve`):**
   - Запрос `/cards/<name>.jpg` прозрачно перенаправляется в `assets/cards/web/<name>.jpg` (560×840 вместо 700×1050, суммарно 661 КБ вместо 1165 КБ).
   - Запрос `/sounds/<night|day|vote>_ambient.wav` перенаправляется в `assets/sounds/web/...` (16 кГц, 12 с с кроссфейдом вместо 22 кГц 20–30 с; 359 КБ на файл вместо 818–1313 КБ).
   - В итоге первый заход браузерного игрока весит **~1.35 МБ вместо 5.1 МБ** (27 МБ вместо 102 МБ на стол из 20 человек).
6. **ETag (`"v5-<hexLength>"`) + `304 Not Modified` + редирект ошибок:** вся статика (кроме HTML) отдаётся с `Cache-Control: public, max-age=604800, immutable` и `ETag`. Неизвестные URL перенаправляются (`302 Found`) на `/`, а пути с `..` отвергаются.

### Защита сокетов в `HostServer`
- Сокеты, открытые и не прошедшие регистрацию (`playerId == null`) за **30 секунд**, принудительно закрываются.
- Отсутствие `ping` от игрока дольше **12 секунд** (`Net.pingTimeout`) генерирует одиночное событие `onPlayerLost`.
- Антифлуд: если клиент шлёт более **60 сообщений за 10 секунд**, его входящие пакеты игнорируются.
- Метод `broadcast()` сериализует JSON `env.encode()` **один раз** на все 20 сокетов.

## 7. Синхронизация часов и звука между устройствами

Системные часы на телефонах игроков могут расходиться на десятки секунд или минуты. Чтобы драматические звуки (наступление ночи, выстрел, утро, голосование) звучали **единым залпом** со всех телефонов за столом, и в Dart (`lib/services/synced_audio.dart`), и в JS (`Clock` в `assets/web/app.js`) реализован одинаковый NTP-алгоритм:

1. Каждые 5 секунд клиент отправляет `ping` со своим локальным временем `t0 = DateTime.now()`.
2. Сервер мгновенно возвращает `pong` с `echo = t0` и временем сервера `t1 = hostTime`.
3. Клиент в момент получения `t2` считает:
   - `rtt = t2 - t0` (отбрасываются замеры `< 0` или `> 5000` мс);
   - `offset = t1 - (t0 + rtt / 2)`.
4. Хранится скользящее окно из **24 последних замеров**. Из них выбираются **3 замера с минимальным `rtt`** (сделанные в момент наименьшей загрузки Wi-Fi), и за итоговый `offset` берётся **медиана** их смещений.
5. Когда ведущий запускает общий звук `_playEverywhere(asset)`, он смотрит худший `bestRttMs` среди живых клиентов и вычисляет фору:
   ```dart
   lead = clamp(350 + worstRttMs, 250, 1500) // мс
   playAt = hostNow + lead
   ```
   Сервер рассылает пакет `sound { asset, playAt, volume }` и сам ставит локальный таймер на `lead`.
6. Каждый клиент переводит `playAt` в собственную шкалу времени: `delay = (playAt - offset) - localNow`. Если `delay > 0` — планирует точный запуск (в браузере через аппаратный таймер `AudioContext.currentTime + delay / 1000`); если пакет опоздал не более чем на `1200` мс — играет немедленно; если опоздал сильнее — пропускает.

В тестах при 20 одновременных клиентах разброс воспроизведения между устройствами составляет **2–4 мс** (ухо человека не различает рассинхрон меньше 15–20 мс).

## 8. Устройство веб-клиента (`assets/web/`) и устойчивость в мобильных браузерах

Мобильный браузер — агрессивная среда: при блокировке экрана или сворачивании вкладки ОС замораживает JS-таймеры и молча обрывает TCP-соединения. Веб-клиент в `assets/web/app.js` спроектирован специально под эти условия:

1. **Бесконечное переподключение с экспоненциальной задержкой и джиттером:** пауза растёт от `0.4 с` до `8 с` со случайной добавкой `0..600 мс`. Случайный разброс предотвращает «шторм подключений», когда роутер моргнул и все 20 телефонов пытаются открыть сокет в одну миллисекунду.
2. **Сторожевой таймер (Watchdog):** клиент отслеживает `lastPongAt`. Если от сервера нет ответов **11 секунд** — плашка статуса предупреждает *«Плохая связь…»*; если **20 секунд** — клиент сам принудительно рвёт «зависший» WebSocket и запускает чистое переподключение.
3. **Таймер фазы по дедлайну (`deadline - Date.now()`):** при приходе `phase`, `sync` или `time_update` вычисляется абсолютный момент окончания `S.deadline = Date.now() + seconds * 1000`. Даже если вкладка проспала в фоне 40 секунд с замороженным `setInterval`, в секунду пробуждения счётчик мгновенно покажет точное оставшееся время. В последние 10 секунд таймер краснеет и пульсирует.
4. **Сохранение хода на стыке обрыва (`S.pendingAction`):** если игрок нажал «Отправить выбор» / «Проголосовать» в момент потери связи и не получил `ack`, действие запоминается с номером `phase` и `round`. Сразу после реконнекта и получения `sync` ход автоматически отправляется повторно (только если фаза и круг ещё те же самые).
5. **Обработка возврата из фона:** слушатели `visibilitychange`, `pageshow` (выход из Safari bfcache) и `online` будят `AudioContext`, запрашивают заново `WakeLock` (`navigator.wakeLock.request('screen')`), немедленно шлют `resync_request` и, если за 4 секунды нет ответа, переоткрывают сокет.
6. **Разблокировка звука в браузерах:** мобильные Safari и Chrome блокируют звук до первого пользовательского жеста. Вызов `Sound.unlock()` привязан к нажатию кнопки «Войти в игру» и повторным касаниям экрана; звук можно выключить кнопкой `🔊/🔇` в шапке (сохраняется в `localStorage['mafia_muted']`).
7. **Адаптация под маленькие экраны (320×568 и выше):**
   - Когда от игрока требуется выбор цели (`canAct && !sent`), крупная карта роли `2:3` сворачивается в узкую полоску `#role-strip` с кнопкой быстрого вызова шторки роли, освобождая экран под список кандидатов.
   - При числе целей `> 6` список `#targets` переключается в двухколоночную сетку `.dense` (на экране SE видно сразу 8–10 имён без прокрутки).
   - Кнопки подтверждения и пропуска стоят в один компактный ряд внизу экрана.
8. **Service Worker (`assets/web/sw.js`):** кеш `mafia-v5`. Для навигации (`/` и `.html`) применяет стратегию *Network-First с откатом в кеш* (чтобы всегда получать свежий код партии `window.__MAFIA__`, но не показывать экран браузера «Нет интернета» при секундном провале Wi-Fi). Для всей статики — *Cache-First*. Пути `/ws` и `/ping` не перехватываются.

### 13.1. Обязательный чек-лист при каждом изменении проекта

1. **Поднять версию в `pubspec.yaml`:** например, с `1.0.5+5` на **`1.0.6+6`**. Без увеличения числа после `+` Android откажется обновлять установленное приложение поверх.

3. **Соблюдать паритет протокола:** если добавляется или меняется поле сетевого сообщения в `HostController`, проверьте его обработку **в обоих клиентах** — основном `assets/web/app.js` и запасном `lib/player/player_controller.dart` (а также версию `V = 1` в `app.js` и `Net.protocolVersion = 1` в `constants.dart`).
4. **Прогнать тесты перед сборкой:** `flutter analyze`, `flutter test`, `node --check assets/web/app.js`.

1. **`lib/models/role.dart`:** добавьте новое значение в `enum RoleType`, опишите статическую константу `Role`, задайте `side`, флаги способностей и `nightOrder`, добавьте в `Role.fromType` и `Role.configurable`.

## 14. Что не проверено на реальных устройствах и открытые вопросы

### 14.1. Требует обязательной полевой проверки на живых телефонах

Разработка и автотесты выполнялись в изолированной Linux-среде без физических радиомодулей и камер, поэтому при первом живом тесте проверьте по чек-листу:
1. **Сканирование обоих QR-кодов штатной камерой iPhone (iOS) и Android** — автоподключение к точке доступа по первому QR (`WIFI:...`) и открытие браузера по второму QR (`http://IP:8088/?g=...`).
2. **Маршрутизация трафика на смартфонах игроков без интернета** — на некоторых прошивках Android/iOS, когда Wi-Fi точка доступа не имеет выхода в интернет, система может пытаться гнать HTTP-запросы в мобильную сеть LTE/5G вместо локального `192.168.x.x` (лечится подтверждением системного диалога *«Не отключаться от этой сети Wi-Fi»* или временным отключением мобильных данных у игрока).
3. **Звук Web Audio в мобильном Safari (iPhone)** — поведение при переключении физического рычажка беззвучного режима на корпусе iPhone и восстановление звука после блокировки/разблокировки экрана.
4. **Длительная работа сервера ведущего (1+ час)** при погашенном экране на оболочках с жёстким энергосбережением (Xiaomi HyperOS/MIUI, Honor/Huawei, Samsung) — при необходимости выдать приложению разрешение «Без ограничений» для батареи.

### 14.2. Открытые продуктовые развилки для будущих версий (`docs/OPEN_QUESTIONS.md`)

**Решено в v1.0.6** (подробности — `docs/OPEN_QUESTIONS.md`):
- ✅ **Первая ночь ждёт всех:** фаза `rolesCheck`, автостарт при 100% подтверждений
  и аварийная кнопка «Начать ночь не дожидаясь» с именами отставших.
- ✅ **Кнопка у ведущего «Показать роль повторно»** — с защитным экраном-предупреждением.
- ✅ **Переименование посреди партии запрещено по умолчанию** (переключатель для редких случаев).

Остаётся открытым для следующих версий:
- **Ручная замена роли конкретному игроку** — рекомендуется не делать; вместо неё
  перезапуск партии с тем же составом (FR-7.8).
- **Передача роли ведущего на другое устройство** и **двойной вход с двух устройств** —
  рекомендации и оценка в `docs/РЕКОМЕНДАЦИИ_РАЗРАБОТЧИКА.md`.
